<task type="auto">
  <name>Task 2: Create api_client.py with NetroAPIClient class</name>
  <files>Netro Sprinklers.indigoPlugin/Contents/Server Plugin/api_client.py</files>
  <action>
Create new file api_client.py with the complete NetroAPIClient implementation:

1. **Module docstring** explaining purpose (HTTP client with throttle management)

2. **Imports:**
   - json, logging from stdlib
   - datetime, timedelta from datetime
   - typing: Any, Callable, Dict, Final, Optional, Set, TypedDict, List
   - requests
   - From constants: all API endpoints, DEFAULT_API_TIMEOUT_SECONDS, THROTTLE_LIMIT_MINUTES, TOKEN_PAUSE_THRESHOLD, TOKEN_WARNING_THRESHOLD
   - From exceptions: ThrottleDelayError, NetroAPIError

3. **TypedDict schemas** for response validation (warning-only):
   - MetaSchema: time, token_remaining, token_reset, last_active, version
   - Expected key sets: EXPECTED_INFO_KEYS, EXPECTED_META_KEYS

4. **NetroAPIClient class** with:
   - `__init__`: Accept timeout, logger, prefs_getter (Callable returning dict), prefs_setter (Callable to set key/value). Initialize throttle state, headers, call _restore_throttle_state()
   - Properties: is_throttled, throttle_expires, token_remaining, should_pause_polling
   - `make_request(url, method, data)`: Core HTTP method with throttle check, error handling, token budget update
   - `_handle_http_error(exc)`: Parse Netro error responses, detect rate limit (error code 3), set throttle state
   - `_update_token_budget(meta)`: Parse token_remaining/token_reset from response meta, log warnings at thresholds, call _save_throttle_state
   - `_save_throttle_state()`: Serialize throttle state to JSON, call prefs_setter
   - `_restore_throttle_state()`: Load from prefs_getter, parse JSON, restore _throttle_until if still in future
   - `_validate_response_schema(response, expected_keys, endpoint)`: Log warnings for missing/extra keys (never raise)
   - Convenience methods: get_device_info(serial), get_schedules(serial), get_moistures(serial), get_sensor_data(serial), start_watering(serial, zones, delay, start_time), stop_watering(serial), set_device_status(serial, status), set_no_water(serial, days), report_weather(serial, data)

5. **Error handling** (match existing plugin.py behavior):
   - ConnectionError: Log once, suppress repeats, re-raise
   - Timeout/ReadTimeout: Log once, suppress repeats, re-raise
   - HTTPError: Check for Netro error code 3 (rate limit) or HTTP 429, set throttle, raise ThrottleDelayError
   - For invalid serial (error code 1), log specific error

Key implementation notes from research:
- Pass logger and prefs callbacks as constructor args to avoid circular imports (never import indigo directly)
- Throttle state stored as JSON in prefs with keys: throttle_until, token_remaining, token_reset, last_saved
- On restore, only apply throttle_until if it's still in the future
- Schema validation is WARNING-only - log missing keys, debug log extra keys, never raise
- Token reset time parsed with "%Y-%m-%dT%H:%M:%S" format
